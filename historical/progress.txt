• For queue authority, we’re late-stage. The migrated WAL operation set now
  includes essentially all major queue mutations: enqueue, active transition/
  rollback, progress, terminal settlement, lease request/heartbeat/release/tab-
  release, retry/requeue, resolver remap/unresolved, cancel/pause, non-profile/
  key-only repair, clear-profile, and compatibility progress sync.

  What’s left is less “move obvious queue writers to WAL” and more cleanup/
  hardening:

  - Broad repair/reconcile still exists and should be narrowed or renamed/
    resolved.
  - Runs/events/progress/pending/nuked maps are still derived compatibility
    state and can lag.
  - Progress compatibility writes are still a real storage volume source.
  - WAL storage shape is still not the per-record segment/cursor design you
    wanted.
  - Need live soak on a large batch after the recent slices, with stats on WAL
    tail, checkpoint switches, storage bytes, timeouts, failures, and queue
    accounting drift.
  - Terminology cleanup remains: repair/compaction language should be replaced
    when things calm down.

  So: queue-authority migration feels around 85-90% done. The broader storage
  architecture is more like 65-75% done because the queue authority path is
  mostly there, but derived compatibility state and WAL physical layout are
  still substantial. I’d do one audit slice to prove no direct queue writers
  remain, then live soak, then decide whether to attack progress compatibility
  volume or WAL segment layout next.
